# DDR3 MPR と RVALID のサイクル位置診断

`TangDdrMprAlignProbe` は、既存の MPR 受信遅延スイープと同じ 8 遅延値、64 ゲート設定を走査する。各設定で 3 回 READ し、`RVALID` を基準とする直前・同一・直後の controller clock の DQ0/DQ8 8 beat パターンを並行して比較する。同じ設定の 3 回すべてで同じ位置が `AA` または `55` に一致した場合のみ、そのレーンの位置を合格とする。これにより、`RVALID` と `IDES8_MEM` 出力のサイクル対応を同一 bitstream で比較できる。

UART は `SAA BB CC DD` を空白なしの 9 文字で繰り返す。`S` は状態、`AA` は lane 0 の位置マスク、`BB` は lane 1 の位置マスク、`CC` と `DD` は最後の `RVALID` で観測した DQ0/DQ8 のパターンである。位置マスクの bit 0、1、2 はそれぞれ直前、同一、直後の controller clock に対応する。`M` は両レーンで少なくとも一つの位置が合格したことを示し、合格した位置が両レーンで同じことは保証しない。各位置マスクは全遅延・ゲート設定の論理和であり、単独では有効な連続アイ幅を表さない。

固定済み Gowin コンテナで `DDR_MPR_ALIGN=1 bash scripts/build_ddr_mpr.sh` を実行し、`scripts/test-ddr-init-board.ps1 -Mode DdrMprAlign` で実機を検証する。検証スクリプトは UART の判定結果にかかわらず既知の LCD サンプルを復元する。`make ddr-mpr-align-test` は 1536 READ と 28 delay pulse、両レーン独立の前・同・後判定、および 1 回だけの偽陽性を除外することを確認する。

この診断結果が安定しても、DDR アレイの書込み・読戻し、refresh、アドレス alias、Linux 用メモリ境界は別途検証が必要である。

2026-09-22 の Tang Primer 20K 実機試験では、同一 bitstream SHA256 `69435ad9a1d9fc5c10404ebc1d793f55036d37ac6b2162f82bdfed7575a7c822` を 4 回 SRAM にロードした。定常 UART フレームは順に `M0707BDBD`、`M01010F0B`、`M01010F0B`、`M0707FDBD` だった。各試験後の LCD サンプル復元と UART 検査は通過した。生ログは `logs/board/20260922-002302-DdrMprAlign-*`、`002321`、`002355`、`002414` にある。

`01` のときは両レーンで直前サイクルだけが一致する。一方、`07` は同一候補で隣接する 3 サイクルすべてが一致したことを示す。`IDES8_MEM` のデータ出力が有効期間の外でも保持される場合、`07` を一意なサイクル位置として解釈できない。再ロード間で生パターンと位置マスクも変わったため、今回の結果では固定の RVALID 補正値を選べない。次段階では、READ ごとに異なる期待値を与えられるアレイ読出しを使い、データの遷移を測定する必要がある。
